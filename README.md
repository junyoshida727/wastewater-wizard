# 排水処理ヒアリングシステム — Wastewater Wizard

排水処理設備の営業ヒアリングを効率化するウィザード型ヒアリングシートです。
HTMLと計算・検証・図面描画用JavaScriptの構成で、外部サーバー不要・インストール不要で動作します。直接開く場合も `index.html`、`wizard-core.js`、`wizard-flow.js` を同じフォルダーに置いてください。

---

## 機能概要

- **5ステップウィザード**：基本情報 / 水質情報 / 装置オプション / 既存設備 / 現場・施工条件
- **案件別の下書き保存**：ブラウザ内に最大30日保存。案件を選んで再開・削除できる
- **図面形式のフロー図生成**：機器記号・直角配管・計器・機器一覧・図面枠を備えたSVGを生成。全体／100%表示とSVG保存に対応
- **バッチ処理能力の概算チェック**：装置容量と運転条件から必要バッチ数・必要時間・日処理可能量・未処理量を計算し、結果と前提をPDFにも記載
- **PDF出力**：ブラウザ印刷からヒアリング結果をPDFとして保存
- **モバイル対応**：iOS Safari を含むスマートフォンで操作可能

## バッチ処理能力の概算チェック

STEP1で「1日の排水量」「排水処理装置の容量」に加え、以下を入力すると再計算します。

| 条件 | 入力する内容 |
|---|---|
| 運転可能時間（時間/日） | 休止・保守時間を除いた、0より大きく24以下の時間 |
| 1バッチの所要時間（分/回） | 給水・反応・沈殿・排水・汚泥排出など、次のバッチ開始までの全工程。0より大きい値 |
| 容量の有効使用率（%） | 装置容量に対する1回の原水受入量の割合。0より大きく100以下。メーカー仕様・試験結果等から設定 |

追加条件は任意で、既定値はありません。未入力では「未判定」と不足条件を表示し、従来どおりヒアリングシートを作成できます。旧下書きもそのまま復元できます。不正値は修正が必要です。能力不足・時間の余裕なしは確認事項として表示し、確認後は結果を出力できます。

- 有効処理量（m³/回）= 装置容量（L）÷ 1000 × 有効使用率 ÷ 100
- 必要バッチ数 = 1日の排水量 ÷ 有効処理量（端数切り上げ）
- 実行可能バッチ数 = 運転可能時間 × 60 ÷ 所要時間（端数切り捨て）
- 必要運転時間 = 必要バッチ数 × 所要時間 ÷ 60
- 日処理可能量 = 実行可能バッチ数 × 有効処理量
- 未処理量 = 1日の排水量 − 日処理可能量（不足しなければ0）

例：5m³/日、500L、有効使用率80%、8時間/日、90分/回なら、有効処理量0.4m³/回、必要13回に対して実行可能5回、必要19.5時間、日処理可能量2m³、未処理量3m³となります。これは動作説明用の例で、推奨設計値ではありません。

装置1台の順次バッチ処理を対象とし、端数のバッチも1回分の時間を要すると仮定します。既存の「1日のバッチ回数」は範囲選択のため計算には使用しません。表示値は小数第3位に丸めますが、判定には丸める前の値を使い、整数境界の浮動小数点誤差のみ補正します。ピーク流入・原水槽の貯留能力・並列運転・処理水質の適合は判定対象外です。

## 図面形式のSVGフロー図

ヒアリングシート作成後に、白地の概略設備図を表示します。槽は開放槽・円すい底槽、薬品は薬品槽と薬注ポンプ、粉体供給機はホッパー、ろ過装置は分岐配管・ろ過カゴ・共通の受け槽で表現します。機器タグは右側の機器一覧に対応し、薬剤名・添加量などの入力仕様も記載します。

- 原水槽からの流入は標準付属の移送ポンプ TP-01 でポンプアップ。中継槽を選択すると、原水槽 → 中継槽に TP-01、中継槽 → 凝集沈殿槽に追加分の TP-02 を表示します。上澄液は監視槽（選択時）を経て放流、汚泥は汚泥貯槽（選択時）・ろ過系統へ送ります。
- 移送ポンプの吐出配管は槽内から上へ立ち上げ、槽上部を越えて次の槽へ送ります。槽側壁を貫通しません。移送・追加・薬注ポンプの記号は「丸の中にP」で統一しています。
- 薬品はそれぞれ独立した投入線で描画します。粉体供給機使用時は、従来どおり液体凝集剤の薬注ポンプを描きません。
- 凝集沈殿槽のpH計・液位検出はフォーム記載の標準装備として表示し、オプション計器は選択した槽に表示します。計器の丸記号と槽へ伸びる線は実線です。
- 電磁バルブは丸の中に「V」で表示します。凝集沈殿槽の上澄液出口がMV-1、汚泥出口がMV-2、2〜5分岐の各カゴ手前がMV-3以降です。2分岐なら計4個、5分岐なら計7個となります。「分岐なし」・ろ過なし・未確認の場合は枝管側のバルブを追加しません。汚泥貯槽を経由する場合も、MV-2は凝集沈殿槽の出口に配置します。
- 図示した電磁バルブ・pH計・濁度計・レベルセンサーを機器一覧に個別掲載し、図面と同じMV・PH・TU・LSの連番と設置先を記載します。凝集沈殿槽の標準pH計・レベルセンサーはPH-1・LS-1です。その他の計器番号は選択構成に応じて再生成します。「その他」のレベルセンサーは入力台数・設置先を一覧に記載し、位置未確定のため図示・個別採番は行いません。弁の口径・駆動仕様・制御条件は自動決定しません。
- 原水槽の有無が不明・未設置なら破線表示。ろ過が未確認・「ろ過しない」の場合は、ろ過装置・ろ過水放流を描きません。
- ろ過分岐数に応じて1〜5個のカゴを共通のろ過受け槽内に並べ、各カゴの上に枝管を表示します。「分岐なし」は1個です。基本構成は200L＝2分岐、500L＝3分岐、1000L＝5分岐として入力欄に案内し、図面には選択値を反映します。容量による選択値の自動変更は行いません。カゴ数に応じて受け槽・図面の幅を広げ、追加攪拌機はカゴ横に配置します。
- STEP4の追加機器で「ポンプ／攪拌機／その他」と「設置槽」を選択すると、その槽内に機器タグと台数を表示します。複数台は記号を台数分並べず台数で表し、機器行が増えた場合は槽と図面を縦に拡張します。原水槽が未設置・未確認でも、計画上の設置先として選択できます。
- 追加攪拌機は槽上部の「M」モーターから縦軸を下ろし、水面下の2枚の楕円形羽根につなぎます。複数の攪拌機行と計器を並べる場合は、槽幅と後続機器の位置を調整します。
- 図示済みの移送ポンプは追加機器欄に重複入力する必要はありません。薬注ポンプの必要台数計算は従来どおり薬品用のみです。
- 旧下書きの追加機器は種別・設置槽を未指定として保持します。構成から外した槽への割当は確認事項とし、槽や機器を勝手に追加せず一覧に残します。0台の機器は図示しません。
- 追加ポンプは設置場所のみを図示し、吐出先・配管接続を自動決定しません。脱水機も接続未確定として機器一覧に記載します。
- 「全体表示」で図面全体、「100%表示」で細部を確認できます。狭い画面では図面内を横スクロールできます。
- 「SVGを保存」で図面のみをベクター形式で保存します。通常のPDF出力にも図面が入り、100%表示中でも紙幅に合わせて縮小します。細部の確認には保存したSVGの拡大表示を利用してください。

この図面は計画検討用・縮尺NTS（実寸比を持たない概略図）です。配管口径、弁種、材質、制御配線、機器型番、設置寸法は自動決定しません。参考図の固有仕様を複製せず、処理水質や前処理構成の確定は従来どおり別途確認します。

## 構成とテスト

- `index.html`：入力画面、保存・復元、結果表示、SVG、印刷スタイル
- `wizard-core.js`：データ初期化・旧データ正規化・入力検証・計算（DOMに依存しない）
- `wizard-flow.js`：機器記号、配管経路、計器、機器一覧、図面表題欄を生成する独立SVG描画モジュール（DOM・外部ライブラリに依存しない）
- `tests/wizard-core.test.mjs`：計算、境界値、不正値、旧下書きの互換性
- `tests/capacity-integration.test.mjs`：実際の入力ハンドラー、保存・復元、新規案件、結果転記、HTMLエスケープ、SVG表示切替・ダウンロード、追加機器の入力・復元・結果反映（簡易DOMで検証）
- `tests/wizard-flow.test.mjs`：ポンプアップ経路、機器選択・設置槽への配置、薬注ポンプ、計器の実線、未確認条件、長文、多薬品、多機器、SVGエスケープの検証
- `tests/static.test.mjs`：既存の復元・PDF転記・スクリプト構文の回帰確認

ブラウザでは上記の例を入力後、装置容量・運転条件を変更して判定が切り替わること、再読み込み→再開で値が戻ること、新規案件で空欄になることを確認してください。結果画面と印刷プレビューに計算条件・計算結果・前提が表示されることも確認します。

## ローカル開発

### 必要環境
- Node.js 20 以上

### セットアップ

```bash
# 依存パッケージのインストール
npm install

# ローカルサーバー起動（http://127.0.0.1:3000）
npm run dev

# 入力・復元・計算・PDF転記のテスト
npm test
```

## ブランチ運用

| ブランチ | 用途 |
|---|---|
| `main` | 本番（GitHub Pages への自動デプロイ対象） |
| `dev` | レビュー済み変更を集約する開発ブランチ |
| `feature/*` | 新機能開発 |
| `fix/*` | バグ修正 |
| `chore/*` | 開発環境・CI・依存関係の整備 |
| `docs/*` | ドキュメントのみの変更 |
| `codex/*` | Codex主導の保守作業 |

### 開発フロー

```
dev から作業ブランチを作成
    ↓
実装・npm test・印刷プレビュー確認
    ↓
Pull Requestでレビュー
    ↓
dev へマージ
    ↓
本番反映時に dev → main へマージ
```
