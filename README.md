# 排水処理ヒアリングシステム — Wastewater Wizard

排水処理設備の営業ヒアリングを効率化するウィザード型ヒアリングシートです。
HTMLと計算・検証用JavaScriptの構成で、外部サーバー不要・インストール不要で動作します。直接開く場合も `index.html` と `wizard-core.js` を同じフォルダーに置いてください。

---

## 機能概要

- **5ステップウィザード**：基本情報 / 水質情報 / 装置オプション / 既存設備 / 現場・施工条件
- **案件別の下書き保存**：ブラウザ内に最大30日保存。案件を選んで再開・削除できる
- **フロー図生成**：ヒアリング内容に応じた SVG プロセスフロー図を自動生成
- **バッチ処理能力の概算チェック**：装置容量と運転条件から必要バッチ数・必要時間・日処理可能量・未処理量を計算し、結果と前提をPDFにも記載
- **PDF出力**：ブラウザ印刷からヒアリング結果をPDFとして保存
- **モバイル対応**：iOS Safari を含むスマートフォンで操作可能

## バッチ処理能力の概算チェック

STEP1で「1日の排水量」「排水処理装置の容量」に加え、以下を入力すると再計算します。

| 条件 | 入力する内容 |
|---|---|
| 運転可能時間（時間/日） | 休止・保守時間を除いた、0より大きく24以下の時間 |
| 1バッチの所要時間（分/回） | 給水・反応・沈殿・排水・汚泥排出など、次のバッチ開始までの全工程。0より大きい値 |
| 容量の有効使用率（%） | 装置容量に対する1回の原水受入量の割合。0より大きく100以下。メーカー仕様・試験結果等から設定 |

追加条件は任意で、既定値はありません。未入力では「未判定」と不足条件を表示し、従来どおりヒアリングシートを作成できます。旧下書きもそのまま復元できます。不正値は修正が必要です。能力不足・時間の余裕なしは確認事項として表示し、確認後は結果を出力できます。

- 有効処理量（m³/回）= 装置容量（L）÷ 1000 × 有効使用率 ÷ 100
- 必要バッチ数 = 1日の排水量 ÷ 有効処理量（端数切り上げ）
- 実行可能バッチ数 = 運転可能時間 × 60 ÷ 所要時間（端数切り捨て）
- 必要運転時間 = 必要バッチ数 × 所要時間 ÷ 60
- 日処理可能量 = 実行可能バッチ数 × 有効処理量
- 未処理量 = 1日の排水量 − 日処理可能量（不足しなければ0）

例：5m³/日、500L、有効使用率80%、8時間/日、90分/回なら、有効処理量0.4m³/回、必要13回に対して実行可能5回、必要19.5時間、日処理可能量2m³、未処理量3m³となります。これは動作説明用の例で、推奨設計値ではありません。

装置1台の順次バッチ処理を対象とし、端数のバッチも1回分の時間を要すると仮定します。既存の「1日のバッチ回数」は範囲選択のため計算には使用しません。表示値は小数第3位に丸めますが、判定には丸める前の値を使い、整数境界の浮動小数点誤差のみ補正します。ピーク流入・原水槽の貯留能力・並列運転・処理水質の適合は判定対象外です。

## 構成とテスト

- `index.html`：入力画面、保存・復元、結果表示、SVG、印刷スタイル
- `wizard-core.js`：データ初期化・旧データ正規化・入力検証・計算（DOMに依存しない）
- `tests/wizard-core.test.mjs`：計算、境界値、不正値、旧下書きの互換性
- `tests/capacity-integration.test.mjs`：実際の入力ハンドラー、保存・復元、新規案件、結果転記、HTMLエスケープ（簡易DOMで検証）
- `tests/static.test.mjs`：既存の復元・PDF転記・スクリプト構文の回帰確認

ブラウザでは上記の例を入力後、装置容量・運転条件を変更して判定が切り替わること、再読み込み→再開で値が戻ること、新規案件で空欄になることを確認してください。結果画面と印刷プレビューに計算条件・計算結果・前提が表示されることも確認します。

## ローカル開発

### 必要環境
- Node.js 20 以上

### セットアップ

```bash
# 依存パッケージのインストール
npm install

# ローカルサーバー起動（http://127.0.0.1:3000）
npm run dev

# 入力・復元・計算・PDF転記のテスト
npm test
```

## ブランチ運用

| ブランチ | 用途 |
|---|---|
| `main` | 本番（GitHub Pages への自動デプロイ対象） |
| `dev` | レビュー済み変更を集約する開発ブランチ |
| `feature/*` | 新機能開発 |
| `fix/*` | バグ修正 |
| `chore/*` | 開発環境・CI・依存関係の整備 |
| `docs/*` | ドキュメントのみの変更 |
| `codex/*` | Codex主導の保守作業 |

### 開発フロー

```
dev から作業ブランチを作成
    ↓
実装・npm test・印刷プレビュー確認
    ↓
Pull Requestでレビュー
    ↓
dev へマージ
    ↓
本番反映時に dev → main へマージ
```
